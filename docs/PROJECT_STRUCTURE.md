# Project Structure

What each folder and file in this repo is for.

```
gpu-telemetry/
├── .github/workflows/   # CI pipeline
├── cmd/                 # entry points: one small main.go per program
├── internal/            # all the real code
│   ├── mq/              # the custom message queue
│   ├── streamer/        # CSV → queue
│   ├── collector/       # queue → database
│   ├── store/           # database layer
│   ├── api/             # REST API
│   ├── telemetry/       # data point + CSV parser
│   └── platform/        # shared helpers
├── test/e2e/            # full-pipeline system test
├── data/                # sample telemetry CSV
├── docs/                # design docs + generated OpenAPI spec
├── deploy/helm/         # Kubernetes Helm chart
├── scripts/             # smoke test
└── (top-level files)    # build, run, README
```

---

## `cmd/`: the four programs

Each `main.go` only reads settings from environment variables and starts the
service. There's no business logic here.

| File | Program |
|---|---|
| `cmd/streamer/main.go` | Reads the CSV and publishes to the queue |
| `cmd/broker/main.go` | The message queue server |
| `cmd/collector/main.go` | Reads from the queue and writes to the database |
| `cmd/api/main.go` | The REST API server (also holds the OpenAPI title/version) |

## `internal/`: the application code

### `internal/mq/`: the custom message queue

| File | What it does |
|---|---|
| `types.go` | Shared types (message, record, wire formats), errors, and the key-to-partition hash |
| `wal.go` | Write-ahead log: saves records to disk as checksummed frames, and recovers after a crash |
| `partition.go` | One partition: a memory ring buffer plus the log, backpressure, and long-poll reads |
| `membership.go` | Heartbeats and leases, consumer groups, round-robin partition assignment, fenced commits |
| `broker.go` | Ties it together: partitions, groups, the streamer registry, and saving offsets |
| `server.go` | The broker's HTTP API (publish, fetch, heartbeat, commit) |
| `client.go` | HTTP client used by streamers and collectors to talk to the broker |
| `consumer.go` | Collector-side loop: joins the group, runs one worker per owned partition, commits |

### `internal/streamer/`

| File | What it does |
|---|---|
| `streamer.go` | Loops over the CSV, stamps each row with `time.Now()`, publishes only the GPUs in its shard |

### `internal/collector/`

| File | What it does |
|---|---|
| `collector.go` | Decodes a batch from the queue, skips bad records, writes the rest to the database |

### `internal/store/`: the database layer

| File | What it does |
|---|---|
| `store.go` | The storage interface, query and page types, and `Connect` |
| `postgres.go` | TimescaleDB implementation: batched writes, paginated queries |
| `memory.go` | In-memory implementation, used by tests |
| `schema.sql` | Table definitions: `gpus`, `telemetry` hypertable, unique key, 7-day retention, compression |

### `internal/api/`

| File | What it does |
|---|---|
| `server.go` | REST endpoints, input validation, cursor pagination, health checks, Swagger UI |

### `internal/telemetry/`

| File | What it does |
|---|---|
| `point.go` | The telemetry data point and its validation |
| `csv.go` | Parses DCGM CSV rows (finds columns by header name, parses labels) |

### `internal/platform/`

| File | What it does |
|---|---|
| `platform.go` | Shared helpers: env settings, JSON logging, HTTP server with timeouts, graceful shutdown, retry with backoff |

### Unit tests

Each `*_test.go` file sits next to the code it tests (for example
`partition_test.go` tests `partition.go`). Run them all with `make test`.

## `test/e2e/`: system test

| File | What it does |
|---|---|
| `pipeline_test.go` | Runs the whole pipeline in-process (broker, 2 streamers, 2 collectors, API) on the real CSV and checks all 247 GPUs come through |

## `docs/`: design docs and OpenAPI spec

| File | What it is |
|---|---|
| `HLD.md` | High-level design |
| `AI_USAGE.md` | How AI was used |

| File | What it is |
|---|---|

## `.github/workflows/`

| File | What it does |
|---|---|
| `ci.yml` | On every push and pull request: `go vet`, unit + system tests with the race detector, Helm lint, Docker build |

## `deploy/helm/gpu-telemetry/`: Kubernetes

| File | What it is |
|---|---|
| `Chart.yaml` | Chart name and version |
| `values.yaml` | Settings: replicas, partitions, storage, resources |
| `templates/_helpers.tpl` | Shared labels and the secure container settings (non-root, read-only) |
| `templates/broker.yaml` | Broker StatefulSet + Service (with a persistent volume for the log) |
| `templates/timescaledb.yaml` | Database StatefulSet + Service |
| `templates/workers.yaml` | Streamer and collector Deployments |
| `templates/api.yaml` | API Deployment + Service |
| `templates/secret.yaml` | Generated database password (kept across upgrades) |
| `templates/networkpolicy.yaml` | Only allowed services can reach the broker and the database |

## `scripts/`

| File | What it does |
|---|---|
| `smoke_test.sh` | 13 live checks against the running stack (GPUs, ordering, filters, pagination, errors). Run by `make demo` |

## Top-level files

| File | What it is |
|---|---|
| `Makefile` | All commands: `make demo`, `make test`, `make coverage`, `make openapi`, `make scale`, `make helm-install` |
| `run.sh` | Start without `make`: `./run.sh` (stop with `./run.sh down`) |
| `Dockerfile` | Builds one small, non-root image containing all four programs |
| `docker-compose.yml` | Runs the database, broker, streamer, collector and API locally |
| `go.mod` / `go.sum` | Go module name and pinned dependency versions |
| `README.md` | How to run, architecture, API, testing |
| `.gitignore` | Files git skips: `.env`, coverage reports, binaries |
| `.dockerignore` | Files kept out of the Docker build (`.git`, `.env`, Helm chart, ...) |

**Generated locally, not committed:**

| File | What it is |
|---|---|
| `.env` | Database password, generated on first run (secret, never commit) |
| `coverage.out` / `coverage.html` | Test coverage reports from `make coverage` |
